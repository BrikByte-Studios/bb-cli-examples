# Phase 0 Basic Project

This is the smallest useful BrikByteOS `bb` example project.

It teaches the basic Phase 0 workflow:

```text
initialize project
check runtime readiness
validate configuration
run a Phase 0 adapter
generate a report
evaluate a quality gate
```

This example is intentionally small, safe, and beginner-friendly.

---

## Prerequisites

Install `bb` from the public release repository.

Linux/macOS:

```bash
curl -sSL https://raw.githubusercontent.com/BrikByte-Studios/bb-cli-releases/main/install.sh | bash
```

Install a specific release candidate:

```bash
curl -sSL https://raw.githubusercontent.com/BrikByte-Studios/bb-cli-releases/main/install.sh | bash -s -- --version v0.1.0-rc.3
```

Verify installation:

```bash
bb version
```

Expected output should include:

```text
BrikByteOS bb
Version:
Commit:
Built:
OS/Arch:
```

If your shell finds an old `bb` binary first, run the installed binary directly:

```bash
$HOME/.local/bin/bb version
```

## Quick Start

From this directory:

```bash
./scripts/run-example.sh
```

Or run the commands manually:

```bash
bb version
bb init
bb doctor
bb config validate
bb run
bb report
bb gate
```

## Run From Repository Root

From the `bb-cli-examples` repository root:

```bash
bb --workdir examples/phase0-basic-project init
bb --workdir examples/phase0-basic-project doctor
bb --workdir examples/phase0-basic-project config validate
bb --workdir examples/phase0-basic-project run
bb --workdir examples/phase0-basic-project report
bb --workdir examples/phase0-basic-project gate
```

Or use the root Makefile:

```bash
make run-basic-example
```

## Important Generated Files

Running this example creates local runtime artifacts:

```text

.bb/
```

These files are generated by `bb init`, `bb run`, `bb report`, and `bb gate`.

They are intentionally ignored by Git.

## Expected Phase 0 Workflow

### 1. Version

```bash
bb version
```

Shows the installed `bb` version and build metadata.

---

### 2. Initialize

```bash
bb init
```

Creates:

```text
bb.config.yaml
.bb/runs/
```

---

### 3. Doctor

```bash
bb doctor
```

Checks local Phase 0 runtime readiness.

---

### 4. Config Validate

```bash
bb config validate
```

Validates the generated `bb.config.yaml`.

---

### 5. Run

```bash
bb run
```

Runs the built-in Phase 0 dummy adapter and creates run artifacts.

---

### 6. Report

```bash
bb report
```

Generates or displays the report for the latest run.

---

### 7. Gate

```bash
bb gate
```

Evaluates the quality gate for the latest run.

## Troubleshooting

### `bb: command not found`

Your install directory may not be on your `PATH`.

Default Linux/macOS install directory:

```text
$HOME/.local/bin
```

Add it to your shell profile:

```bash
export PATH="$HOME/.local/bin:$PATH"
```

Or run `bb` directly:

```bash
$HOME/.local/bin/bb version
```

---

### Wrong `bb` Version Is Running

Check all matching binaries:

```bash
type -a bb
which -a bb
```

If you see an old binary before `$HOME/.local/bin/bb`, update your `PATH`:

```bash
export PATH="$HOME/.local/bin:$HOME/go/bin:$PATH"
hash -r
rehash 2>/dev/null || true
```

Then verify:

```bash
which bb
bb version
```

---

### `bb config validate` Fails Before `bb init`

Run:

```bash
bb init
```

Then:

```bash
bb config validate
```

`bb config validate` expects a generated `bb.config.yaml`.

---

### `bb report` or `bb gate` Fails Before `bb run`

Run:

```bash
bb run
```

Then:

```bash
bb report
bb gate
```

`bb report` and `bb gate` depend on run artifacts created by `bb run`.
